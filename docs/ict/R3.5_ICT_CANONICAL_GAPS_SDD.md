## 3) Conceptos (definiciones operativas)

### 3.1 Breaker Block / MMXM

- **Breaker Block**: OB previo que **falló** (precio cerró del lado opuesto) y, tras CHOCH/MSS, **cambia de rol**:
  - bearish OB rota desde arriba → Bullish Breaker (soporte).
  - bullish OB rota desde abajo → Bearish Breaker (resistencia).
- **MMXM (Mitigation)**: el breaker puede ser mitigado **una sola vez**. Luego, se invalida permanentemente.

### 3.2 OTE (Optimal Trade Entry)

- Entry en retrace a **62%–79%** (Fibonacci) de la pierna impulsiva previa.
- LONG: banda = `[high - 0.786*r, high - 0.618*r]`
- SHORT: banda = `[low + 0.618*r, low + 0.786*r]`
- `r = swing_high - swing_low` medido sobre pierna previa clara (detectada por `detect_market_structure`).

### 3.3 SMT Divergence

- Smart Money Techniques/Concepts en este proyecto se definen como detección de **presencia institucional** sin indicadores externos.
- Para este SDD, SMT Divergence = comparación direccional entre:
  - **activo objetivo** (`symbol`),
  - y **par correlato sugerido por config** (ej. EURUSD ↔ DXY), en el **mismo TF**.
- Señal: precio hace higher-high y el correlato hace lower-high (o viceversa). **No es oscillator estándar**; es divergencia de extremos direccionales en dos series sincronizadas.

## 4) Contratos de integración

### 4.1 Datos de entrada (sin ATR ni indicadores)

- `frames[ltf]` con `time, open, high, low, close`.
- Columnas de estructura ya detectadas: `ob_bullish`, `ob_bearish`, `ob_top`, `ob_bottom`, `fvg_bullish`, `fvg_bearish`, `bos_dir`, `choch_dir`, `swing_high`, `swing_low`.
- Para OTE se usa exclusivamente `swing_high/swing_low`.
- Para Breaker/MMXM se usan `ob_*` y `close/sweep_at/entry_at`.
- Para SMT Divergence se necesita un segundo DataFrame `corr_df` en el mismo TF y ventana sincronizada.

### 4.2 Salida canónica

No se tocan `entry/SL/TP` por estos flags. Se anexan campos a `ICTSignal`:

```python
# engine.py (campos nuevos)
breaker_active: bool | None = None
breaker_type: str | None = None
mitigation_level: float | None = None
breaker_strength: float | None = None
ote_confirmed: bool | None = None
ote_zone: tuple[float, float] | None = None
smt_divergence_active: bool | None = None
smt_divergence_direction: int | None = None
smt_divergence_strength: float | None = None
```

Nota: Python permite `setattr` en runtime, pero agregar los campos en `ICTSignal` da tipado y descubrimiento.

## 5) Implementación matemática

### 5.1 Fibonacci OTE (banda 62–79%)

```python
def fib_ote_band(swing_high: float, swing_low: float, direction: int) -> tuple[float, float]:
    r = float(swing_high) - float(swing_low)
    if r <= 0:
        raise ValueError("rango de pierna no positivo")
    if direction == 1:
        return swing_high - 0.786 * r, swing_high - 0.618 * r
    return swing_low + 0.618 * r, swing_low + 0.786 * r
```

Reglas duras:
- No inventar `swing_high/swing_low` si el MS no entrega valores válidos en `entry_at`.
- No cambiar TP por OTE.
- No filtrar señales por OTE.
- OTE es metadato de quality score / observador / backtest descriptivo.

### 5.2 Breaker Block + MMXM

Concepto de fuerza:
```python
strength = sqrt(recency * size_ratio)
```
- `recency = 1 - min(bars_since / max_bars, 1)`
- `size_ratio = min(zone_range / avg_range, 1)` si `avg_range > 0`, else `0.5`.

Reglas:
- Validar OB rota: bearish OB con close > top → bullish breaker candidato; y viceversa.
- El OB debe estar al menos una barra antes de `current_idx` (`end_idx < current_idx`).
- MMXM: desde `current_idx+1` en adelante, si el precio vuelve a entrar en la zona, el breaker queda invalidado (único toque permitido).
- `mitigation_level` = nivel que el mercado mitigó; se usa como Zona/Bonus, no como SL mágico.

### 5.3 SMT Divergence

Comparación por ventana sincronizada `W` (ej. 20–50 velas).

```python
def smt_diverge(base: pd.Series, corr: pd.Series, lookback: int = 40) -> dict:
    win_b = base.iloc[-lookback:]
    win_c = corr.iloc[-lookback:]
    b_hl = win_b["high"].idxmax(), win_b["low"].idxmin()
    c_hl = win_c["high"].idxmax(), win_c["low"].idxmin()
    # Detectar divergencia simple
    bullish = (win_b["close"].iloc[-1] > win_b.iloc[b_hl[0]]["close"]) and \
              (win_c["close"].iloc[-1] < win_c.iloc[b_hl[0]]["close"])
    bearish = (win_b["close"].iloc[-1] < win_b.iloc[b_hl[1]]["close"]) and \
              (win_c["close"].iloc[-1] > win_c.iloc[b_hl[1]]["close"])
    return {
        "active": bullish or bearish,
        "direction": 1 if bullish else (-1 if bearish else 0),
        "strength": float(abs(win_b.iloc[-1]["close"] - win_b.iloc[b_hl[0]]["close"])) / avg_range if bullish else ...
    }
```

Criterios:
- Series deben ser comparables en escala (se puede normalizar por `(x - mean)/std` si hace falta).
- Si el correlato no existe en `frames`, `smt_divergence_* = None`.
- Es un **bonus only**; no veta entrada.

## 7) Backtesting y validación

### 7.1 Criterios No-Go

- Si la variante con estos flags reduce N significativamente sin mejorar PF/WR, se mantiene como **bono solo**.
- Si el flag OTE/SMT/MMXM introduce gates que matan N, se deja únicamente como metadata.
- Si SMT Divergence no muestra correlación real en EURUSD/DXY sobre 12 meses, se vuelve a evaluar el par correlato.

### 7.2 Métricas a medir

| Métrica | Fuente | Target |
|---|---|---|
| Brecha D cumplida | Tests + backtest | N no cambia |
| OTE prevalence | Flag sobre `no_session` XAUUSD | >=5% (sino, recalibrar banda) |
| SMT Divergence active rate | Flag sobre EURUSD M15 | >=3% y >1 trade |
| MMXM invalidation rate | Flag | comparable a 1 touch por breaker activo |
| Regression PF baseline | vs canonical 2026-07-22 | delta <= 1e-3 |

### 7.3 Backtest recomendado

- Correr en `no_session`×EURUSD M15 últimos 8000 velas.
- Reportar:
  - `signals_before` / `signals_after` (debe ser igual).
  - `trade_metrics` previos y posteriores (deben ser iguales).
  - Distribución de flags activos.
- Correr en `no_session`×GBPUSD y XAUUSD si hay datos.
